- Kolmogorov (KolmogorovAnalyzer) runs zlib.compress(level=9) on both strings and computes two numbers: complexity_ratio (how much smaller the zlib of compressed is vs. original — expected to be well below 1.0) and information_efficiency (bits of zlib content per raw character — should be higher for compressed, since CLLM removes redundancy). The pass condition is lenient because structurally simpler output is expected and healthy, not a failure.
Conditional Entropy (ConditionalEntropyAnalyzer) is where the real semantic validation happens and got the most attention. It parses the CLLM token string into a slot dictionary, extracts the same slots from the original using lightweight regex rules, then aligns them and counts what's missing. It distinguishes between slots_lost (meaningful content dropped) vs. acceptable_loss (filler, pleasantries, exact phrasing — safe to lose). Residual entropy is estimated at 4 bits per lost high-value slot. This gets 50% weight in the final retention score because it's the most direct answer to "did we lose meaning?"
- Perplexity (PerplexityAnalyzer) sends both the original and compressed to Claude Haiku (cheapest, fastest) with the same structured JSON extraction task, then compares the responses across three dimensions: fact overlap (40%), field-level Jaccard similarity (40%), and JSON structure preservation (20%). It falls back gracefully to heuristic token overlap when no API key is present — useful for CI/CD runs where you don't want an API dependency.
- CompressionQualityAnalyzer is the single entry point. The verdict logic gives conditional entropy veto power — you can be "acceptable" with a borderline perplexity score, but you can't be "lossless" if semantic slots were dropped. The run_perplexity=False flag gives you a fast offline mode for batch validation without burning API calls.
Two things you'll want to adapt: the extract_natural_slots method in CLLMTokenParser should eventually delegate to the Thread Encoder's own extraction logic rather than the lightweight regex rules, so the slot comparison is symmetrical.
